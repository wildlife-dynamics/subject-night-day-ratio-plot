Run form

spec.yaml shapes the form in these ways:

  • rjsf-overrides turns Subject Group Name into a drop-down: the EarthRangerEnumResolver transform fills it with the subject groups of the data source picked under Connect to EarthRanger (depends_on: properties.er_connection.properties.data_source.properties.name).
  • rjsf-overrides $defs limits the Category grouper to Subject Name (ValueGrouper.properties.index_name.oneOf), the only subject column the views are split on.
  • The steps are not in task groups, so each form override is keyed by its step id (e.g. subjectgroup_observations.properties.subject_group_name).
  • The Spatial grouper's Spatial Regions is still a text field. To make it a drop-down of the site's spatial feature groups, add an EarthRangerEnumResolver transform with type: spatial_feature_group on groupers.properties.groupers.
  • Open settings. Set Groupers, Basemap URLs and the Trajectory Segment Filter have no partial values, so they're on the form for each run. Without a ui:order, sections appear in the order of the steps.

How the night/day ratio is calculated

The night_day_ratio statistic of summarize_df (ecoscope-platform) calls ecoscope.analysis.astronomy.get_nightday_ratio on each subject's segments for each date. It compares speed, not distance, so long winter nights or short summer nights don't bias the result:

  • Time is split into local solar days, noon to noon, so each contains one whole night. Night is when the sun is more than 6° below the horizon (civil twilight) at the segment's location.
  • For each solar day: night speed = night distance ÷ observed night hours, day speed = day distance ÷ observed day hours, and share = night speed ÷ (night speed + day speed).
  • Shares are averaged, weighted by each solar day's observed hours, and turned back into a ratio with share ÷ (1 − share): 1 is balanced, above 1 faster at night, below 1 faster by day.
  • A solar day only counts if it has more than 1 hour of observed data in both daylight and darkness. Segments longer than 6 hours are dropped rather than split, because a long gap-bridging segment says nothing about speed within it.

Two caveats from ecoscope: the ratio depends on fix rate, so don't compare collars with different duty cycles (coarser fixes pull the ratio towards 1), and it skews if a track crosses the −180/180° meridian. The is_night flag from Classify Is Night is kept in the saved data but isn't used by the ratio, which works out darkness itself.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-night-day-plot-workflow/ is generated from it by wt-compiler.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_night_day_plot --all
